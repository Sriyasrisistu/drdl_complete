# Oracle Approval Workflow Setup

Run these steps in Oracle before using the new SFEED and GD-T&S approval logins.

## 1. Connect as your application user

If you already created `DRDL_USER`, connect as:

```sql
sqlplus DRDL_USER/mini1912@//localhost:1521/XEPDB1
```

## 2. Create the supervisor login table

```sql
CREATE TABLE APPROVER_USERS (
  APPROVER_ID NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  LOGIN_ID VARCHAR2(50 CHAR) NOT NULL UNIQUE,
  PASSWORD VARCHAR2(255 CHAR) NOT NULL,
  APPROVER_NAME VARCHAR2(100 CHAR) NOT NULL,
  DESIGNATION VARCHAR2(100 CHAR),
  ROLE_CODE VARCHAR2(20 CHAR) NOT NULL,
  STATUS VARCHAR2(20 CHAR) NOT NULL
);
```

## 3. Create the index for login lookup

```sql
CREATE INDEX IDX_APPROVER_LOGIN_ID ON APPROVER_USERS (LOGIN_ID);
```

## 4. Insert the SFEED supervisor login

```sql
INSERT INTO APPROVER_USERS (LOGIN_ID, PASSWORD, APPROVER_NAME, DESIGNATION, ROLE_CODE, STATUS)
VALUES ('sfeed01', 'pass123', 'Head, SFEED', 'Supervisor', 'SFEED', 'ACTIVE');
```

## 5. Insert the GD-T&S supervisor login

```sql
INSERT INTO APPROVER_USERS (LOGIN_ID, PASSWORD, APPROVER_NAME, DESIGNATION, ROLE_CODE, STATUS)
VALUES ('gdts01', 'pass123', 'Head, GD-T&S', 'Supervisor', 'GDTS', 'ACTIVE');
```

## 6. Commit the changes

```sql
COMMIT;
```

## 7. Verify the new accounts

```sql
SELECT LOGIN_ID, APPROVER_NAME, ROLE_CODE, STATUS
FROM APPROVER_USERS;
```

Expected demo logins:

- `sfeed01 / pass123`
- `gdts01 / pass123`

Notes:

- The existing `SAFETY_REQUEST` table already has `HEAD_SFEED_STATUS`, `WORK_ALLOCATED_TO`, and `GD_TS_STATUS`, so you do not need to add new approval status columns.
- The app will use those existing columns for request submission and approvals.
